# CRM Stage 1, PR 0 — UUID-Native Schema Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every domain table UUID v7-keyed from the first migration, before any CRM model is written.

**Architecture:** The `quill` MySQL schema is empty and nothing is deployed, so there is no data to preserve and therefore no conversion to perform. The existing `create` migrations are edited in place to use `uuid` primary keys and `foreignUuid` references, and the models pick up Laravel's `HasUuids` trait, which generates UUID v7 (`Str::uuid7()`) — time-ordered, so index locality stays comparable to auto-incrementing integers.

**Tech Stack:** PHP 8.5, Laravel 13, MySQL 9.4, Pest 5, PHPStan (larastan) level 7, Pint.

## Why this replaced a conversion plan

An earlier version of this plan performed a real, data-preserving conversion of five
`bigint` tables. It was written when the development database was a 2 MB SQLite file
with real rows in it. The move to MySQL landed on an empty `quill` schema, which
removed the only reason that work existed. Editing the original migrations is smaller,
carries no risk of a half-converted table, and leaves no throwaway migration in
history for the next reader to puzzle over.

The abandoned approach and its reasoning are in git history at `4f7539b` if a
data-preserving conversion is ever needed for a deployed environment.

## Global Constraints

- PHPStan stays at **level 7**. Do not raise it. (`.ai/rules/general.md`)
- Models carry **exactly one docblock**: `/** @mixin IdeHelperX */`. (`.ai/rules/models.md`)
- `protected $guarded`, never `$fillable`. `#[UseFactory(...)]` + `HasFactory`.
- No `@return` docblocks on relation methods.
- Curly braces on all control structures. Explicit return types and parameter type hints everywhere.
- **Model hooks own derived data.** Slugs are generated by `creating` and regenerated by `updating`. Nothing sets a slug by hand.
- **`HasUuids` sets `$incrementing = false` and `$keyType = 'string'`.** Never set either by hand; remove any existing declaration that fights it.
- **No UUIDs in URLs.** `Team` resolves by `slug`, `TeamInvitation` by `code`. New models follow that pattern.
- **Framework tables stay as they are.** `jobs`, `job_batches`, `failed_jobs`, `cache`, and `cache_locks` are infrastructure, not domain models. `sessions.user_id` changes only because it references `users`.
- **Destructive commands are scoped to the `quill` schema.** The local MySQL server holds ~2250 tables across several unrelated projects. `migrate:fresh` only drops tables in the configured database — verify `database.default` is `mysql` and the database is `quill` before running it.
- Run `vendor/bin/pint --dirty --format agent` before every commit.
- Full gate is `composer test`. Individual runs use `php artisan test --compact --filter=...`.
- **This PR adds no features.** Behaviour before and after is identical; only key types change.

### Task 1: Make the schema UUID-native

**Files:**
- Modify: the four migrations listed above

**Interfaces:**
- Produces: `users.id`, `teams.id`, `team_members.id`, `team_invitations.id`, and
  `passkeys.id` as `uuid` (MySQL `char(36)`); every reference to them as `foreignUuid`.

- [ ] **Step 1: Confirm you are pointed at the right database**

```bash
php artisan config:show database.default
php artisan tinker --execute 'echo config("database.connections.mysql.database");'
```

Expected: `mysql` and `quill`. **Stop if the database is not `quill`** — the next steps
drop tables.

- [ ] **Step 2: Convert the users and sessions migration**

In `database/migrations/0001_01_01_000000_create_users_table.php`, change `$table->id()`
in the `users` table to `$table->uuid('id')->primary();`, and change
`$table->foreignId('user_id')->nullable()->index();` in the `sessions` table to
`$table->foreignUuid('user_id')->nullable()->index();`.

`password_reset_tokens` is unchanged — its primary key is `email`.

- [ ] **Step 3: Convert the passkeys migration**

In `database/migrations/2024_01_01_000000_create_passkeys_table.php`, change
`$table->id();` to `$table->uuid('id')->primary();` and
`$table->foreignId('user_id')->constrained()->cascadeOnDelete();` to
`$table->foreignUuid('user_id')->constrained()->cascadeOnDelete();`.

- [ ] **Step 4: Convert the teams migration**

In `database/migrations/2026_01_27_000001_create_teams_table.php`, for all three tables
change `$table->id();` to `$table->uuid('id')->primary();`, and change every
`foreignId` to `foreignUuid`:

- `teams`: `id`
- `team_members`: `id`, `team_id`, `user_id`
- `team_invitations`: `id`, `team_id`, `invited_by`

Keep every `constrained()`, `cascadeOnDelete()`, `unique()`, and index exactly as it is.

- [ ] **Step 5: Convert the current_team_id migration**

In `database/migrations/2026_01_27_000002_add_current_team_id_to_users_table.php`, change
`$table->foreignId('current_team_id')` to `$table->foreignUuid('current_team_id')`,
leaving `->nullable()->after('password')->constrained('teams')->nullOnDelete()` intact.

- [ ] **Step 6: Verify no integer keys remain in domain migrations**

```bash
grep -n 'id()\|foreignId' database/migrations/*.php
```

Expected: matches only in `0001_01_01_000002_create_jobs_table.php` (framework
infrastructure). Any match in users, teams, or passkeys means a step was missed.

- [ ] **Step 7: Run the migrations against MySQL**

```bash
php artisan migrate:fresh
```

Expected: all migrations run with no errors. A `foreignUuid` referencing a `bigint`
would fail here with `errno: 150`, so a clean run proves every pair matches.

- [ ] **Step 8: Confirm the column types in MySQL**

```bash
php artisan tinker --execute '
$db = config("database.connections.mysql.database");
foreach (DB::select("SELECT table_name AS t, column_name AS c, column_type AS ty
    FROM information_schema.columns
    WHERE table_schema = ? AND (column_name = \"id\" OR column_name LIKE \"%_id\" OR column_name = \"invited_by\")
    AND table_name IN (\"users\",\"teams\",\"team_members\",\"team_invitations\",\"passkeys\",\"sessions\")
    ORDER BY table_name, column_name", [$db]) as $r) {
    echo "{$r->t}.{$r->c}: {$r->ty}".PHP_EOL;
}'
```

Expected: every row reports `char(36)`. `sessions.id` is `varchar(255)` — that is
Laravel's session identifier, not a key, and is correct.

- [ ] **Step 9: Commit**

```bash
vendor/bin/pint --dirty --format agent
git add database/migrations
git commit -m "Key the domain tables by UUID"
```

### Task 2: Teach the models about UUID keys

**Files:**
- Modify: `app/Models/User.php`, `app/Models/Team.php`, `app/Models/TeamInvitation.php`, `app/Models/Membership.php`
- Test: `tests/Feature/UuidKeysTest.php`

**Interfaces:**
- Consumes: the UUID schema (Task 1).
- Produces: every domain model generates a UUID v7 key on create; `Team` still resolves
  by `slug` and `TeamInvitation` by `code`.

- [ ] **Step 1: Write the failing test**

Create `tests/Feature/UuidKeysTest.php`:

```php
<?php

use App\Enums\TeamRole;
use App\Models\Team;
use App\Models\TeamInvitation;
use App\Models\User;
use Illuminate\Support\Str;
use Ramsey\Uuid\Uuid;

test('users get uuid version 7 keys', function () {
    $user = User::factory()->create();

    expect($user->id)->toBeString();
    expect(Str::isUuid($user->id))->toBeTrue();
    expect(Uuid::fromString($user->id)->getVersion())->toBe(7);
});

test('teams get uuid keys and still resolve by slug', function () {
    $team = Team::factory()->create(['name' => 'Acme', 'slug' => 'acme']);

    expect(Str::isUuid($team->id))->toBeTrue();
    expect($team->getRouteKeyName())->toBe('slug');
    expect($team->getRouteKey())->toBe('acme');
});

test('memberships get uuid keys and join correctly', function () {
    $user = User::factory()->create();
    $team = Team::factory()->create();

    $team->members()->attach($user, ['role' => TeamRole::Owner->value]);

    $membership = $team->memberships->first();

    expect(Str::isUuid($membership->id))->toBeTrue();
    expect($membership->user_id)->toBe($user->id);
    expect($membership->team_id)->toBe($team->id);
    expect($user->ownsTeam($team))->toBeTrue();
});

test('invitations get uuid keys and still resolve by code', function () {
    $invitation = TeamInvitation::factory()->create();

    expect(Str::isUuid($invitation->id))->toBeTrue();
    expect($invitation->getRouteKeyName())->toBe('code');
});

test('a personal team is created and selected for every new user', function () {
    $user = User::factory()->create();

    expect($user->personalTeam())->not->toBeNull();
    expect($user->current_team_id)->toBe($user->personalTeam()->id);
    expect(Str::isUuid($user->current_team_id))->toBeTrue();
});
```

- [ ] **Step 2: Run it to verify it fails**

Run: `php artisan test --compact --filter=UuidKeysTest`
Expected: FAIL. With `uuid` columns but no `HasUuids`, MySQL rejects the insert or the
key comes back empty — either way the first assertion fails.

- [ ] **Step 3: Add `HasUuids` to `User`, `Team`, and `TeamInvitation`**

In each model add `use Illuminate\Database\Eloquent\Concerns\HasUuids;` to the imports
and `HasUuids` to the trait list in alphabetical position:

- `app/Models/User.php`: `use HasFactory, HasTeams, HasUuids, Notifiable, PasskeyAuthenticatable, TwoFactorAuthenticatable;`
- `app/Models/Team.php`: `use GeneratesUniqueTeamSlugs, HasFactory, HasUuids, SoftDeletes;`
- `app/Models/TeamInvitation.php`: `use HasFactory, HasUuids;`

- [ ] **Step 4: Fix `Membership`**

`Membership` declares `public $incrementing = true;`, which contradicts `HasUuids`.
Remove that line and add the trait:

```php
class Membership extends Pivot
{
    use HasUuids;

    protected $table = 'team_members';
```

- [ ] **Step 5: Run it to verify it passes**

Run: `php artisan test --compact --filter=UuidKeysTest`
Expected: PASS, 5 tests.

- [ ] **Step 6: Run the whole suite — this is the real check**

Run: `php artisan test --compact`
Expected: PASS. The existing auth, team, settings, and passkey suites are the
regression net for a key-type change. A failure here means a model or relationship was
missed, not that a test is wrong.

- [ ] **Step 7: Regenerate mixins, analyse, commit**

```bash
composer ide-helper
vendor/bin/pint --dirty --format agent
vendor/bin/phpstan analyse
git add app/Models tests/Feature/UuidKeysTest.php _ide_helper_models.php
git commit -m "Give the domain models UUID keys"
```

## What this PR deliberately does not do

- **No new models.** `Organization` and friends arrive in PR 1, born UUID-native.
- **No conversion migration.** There is no data to convert. See "Why this replaced a
  conversion plan" above.
- **No `HasUuids` on framework tables.** `jobs`, `cache`, and `sessions` are
  infrastructure.
- **No route-key changes.** No UUID appears in a URL.

## Notes for the reviewer

- `Str::uuid7()` is time-ordered, so index locality is comparable to auto-incrementing
  integers. This is why the plan uses `HasUuids` rather than `HasVersion4Uuids`.
- MySQL has **no transactional DDL**. It does not matter here — the migrations only ever
  run against an empty schema — but it is why the abandoned conversion plan was risky
  on this engine, and it is worth remembering for any future data migration.
- `PR 1`'s plan (`2026-08-11-crm-organizations.md`) must use `uuid('id')->primary()` and
  `foreignUuid` for `organizations` and `organization_members`. It is updated in the
  same commit range as this plan.
